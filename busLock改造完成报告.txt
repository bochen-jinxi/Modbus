【改造目标】
  解决 SendLoop 启动后读写并发的 5 个风险：
    1. 总线撞车（严重）
    2. 应答错配（严重）
    3. 清状态互相干扰（中等）
    4. frameReceived 误触发（中等）
    5. CPU 占用增加（低）

【改造方案】
  加 busLock 事务级互斥 + ExecuteWrite 清 activeWrite + SendLoop 加 try-catch
  不引入新抽象，最小改动解决真问题。

================================================================================
【具体改动清单】
================================================================================

  ── 改动1：新增 busLock 字段（第 49-53 行）──
    位置：activeWrite 字段下方
    内容：
      static readonly object busLock = new object();
    作用：总线事务锁，保证"整个事务（发+等应答）"独占总线
    注释：说明锁顺序 busLock → io → gate，统一不死锁

  ── 改动2：SendLoop 改造（第 165-225 行）──
    改动点：
      (a) 循环开头加 Monitor.TryEnter(busLock, 0) 非阻塞试
          拿不到说明写事务在执行，Sleep(1) 跳过本轮（写优先）
      (b) try-finally 包住整个事务体，finally 里 Monitor.Exit(busLock)
      (c) sp.Write 加 try-catch，异常时打印日志 + idx++ + continue
          防止发送异常导致线程静默退出
    效果：
      - 写事务执行时读让步，不会两帧并发上总线
      - sp.Write 异常不再终止线程
      - 事务边界完整（含等应答 50ms），不是瞬时互斥

  ── 改动3：WriteLoop 改造（第 540-557 行）──
    改动点：
      (a) ExecuteWrite 调用包进 lock(busLock)
          写事务阻塞等总线锁，保证写命令一定能执行
      (b) 删除调试残留 var xxx = wr.GetHashCode()
    效果：
      - 读事务执行时写等待（最多 50ms+发送时间），写命令延迟可接受
      - 写事务独占总线，不受读轮询干扰

  ── 改动4：ExecuteWrite 改造（第 559-625 行）──
    改动点：
      (a) 整个方法体包进 try-finally
      (b) finally 里 activeWrite = null
    效果：
      - 写完成后清活跃引用，防止迟到回显拿旧 wr 比对
      - 虽然整帧比对会拒绝旧应答，但清掉更干净，消除隐患

【锁顺序验证（防死锁）】
================================================================================

  所有需要多锁的路径，获取顺序统一为 busLock → io → gate：

  路径                              获取顺序                          死锁风险
  ──────────────────────────────────────────────────────────────────
  SendLoop 事务体                   busLock → io（发送）              无
                                    busLock → io → gate（超时清状态）  无
  WriteLoop → ExecuteWrite          busLock → io（发送）              无
                                    busLock → io → gate（清状态）      无
  OnData                            io → gate（不涉及 busLock）        无
  FrameGapLoop → OnFrameGap         gate（不涉及 busLock/io）          无

  ★ busLock 永远在最外层，io 在中间，gate 在最内层，顺序统一，无死锁。
