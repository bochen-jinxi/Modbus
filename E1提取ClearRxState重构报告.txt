三、重构后：提取 ClearRxState 方法
================================================================================

3.1 新增方法（SendLoop 之后、OnData 之前）
--------------------------------------------------------------------------------
    // ★ 清空接收状态：丢弃驱动缓冲里的旧数据 + 丢弃已攒的残帧。
    //   SendLoop 超时分支、ExecuteWrite/ExecuteRead 每次发前都调用，复用统一。
    //   锁顺序 io→gate（与 OnData 一致），不会死锁。
    //   ★ 不含 Ack.Reset()：SendLoop 没有 wr.Ack/rr.Ack，调用方各自 Reset 自己的 Ack。
    static void ClearRxState()
    {
        lock (io) { if (sp.IsOpen) sp.DiscardInBuffer(); }
        lock (gate) { buf.Clear(); }
    }

3.2 SendLoop 超时分支替换
--------------------------------------------------------------------------------
    ClearRxState();   // 丢弃驱动缓冲旧数据 + 已攒残帧

3.3 ExecuteWrite 替换
--------------------------------------------------------------------------------
    ClearRxState();
    wr.Ack.Reset();   // 写请求专属，不放进 ClearRxState

3.4 ExecuteRead 替换
--------------------------------------------------------------------------------
    ClearRxState();
    rr.Ack.Reset();   // 读请求专属，不放进 ClearRxState


四、设计决策：为什么 Ack.Reset() 不放进 ClearRxState
================================================================================

4.1 三处的 Ack 不同
--------------------------------------------------------------------------------
    SendLoop 超时：没有 wr.Ack 也没有 rr.Ack（用的是 pollAck）
    ExecuteWrite：wr.Ack.Reset()
    ExecuteRead：rr.Ack.Reset()
    三处的 Ack 对象不同，无法统一。

4.2 pollAck 的 Reset 也不放进 ClearRxState
--------------------------------------------------------------------------------
    SendLoop 超时分支的 pollAck.Reset() 紧跟在 ClearRxState() 之后，
    但 pollAck.Reset() 是"超时专属"操作（发请求前也 Reset pollAck，但那不是清状态），
    语义不同，不放进 ClearRxState。

4.3 ClearRxState 只做"清接收缓冲"这一件事
--------------------------------------------------------------------------------
    单一职责：清驱动缓冲(DiscardInBuffer) + 清残帧(buf.Clear)
    不混入 Ack/信号操作，调用方各自处理自己的信号。


五、重构收益
================================================================================

5.1 消除重复
--------------------------------------------------------------------------------
    三处相同的两行代码 → 一处方法定义 + 三处一行调用
    修改清状态逻辑只需改一处（如加日志、加锁调整）。

5.2 意图更清晰
--------------------------------------------------------------------------------
    ClearRxState() 名字直接表达"清接收状态"的意图
    比两行 lock + DiscardInBuffer + buf.Clear 更易读。

5.3 锁顺序统一
--------------------------------------------------------------------------------
    三处都用同一个方法，锁顺序 io→gate 必然一致，不会因为某处写反而死锁。
