一、用户问题
================================================================================
else if (curPollSeq > 0) pollAck.Set();
这个是 int curPollSeq，正的最大值后 +1 就是负值，
彼时负值就是有效的值了。


二、结论：用户完全正确，已修复
================================================================================
pollSeq 是 int 类型，Interlocked.Increment 到 int.MaxValue(2147483647) 后
再 +1 会溢出成 int.MinValue(-2147483648)，是负数。
此时 curPollSeq > 0 为 false → Handle 不 Set pollAck → 周期轮询读永远超时。
已改用 volatile bool pollActive 替代 int 序号，bool 只有 true/false，无溢出。


三、溢出风险详细分析
================================================================================

3.1 int 溢出机制
--------------------------------------------------------------------------------
  int 是 32 位有符号整数，范围 -2147483648 ~ 2147483647。
  Interlocked.Increment(ref pollSeq) 在 pollSeq == int.MaxValue 时：
    pollSeq + 1 = 2147483647 + 1 = -2147483648（溢出，绕到负数）
  C# 默认不检查整数溢出（unchecked 上下文），静默绕回。

3.2 溢出后的行为
--------------------------------------------------------------------------------
  pollSeq 溢出成负数后：
    int seq = Interlocked.Increment(ref pollSeq);  // seq = -2147483648
    curPollSeq = seq;                               // curPollSeq = -2147483648
  Handle 中：
    if (curPollSeq > 0)  // -2147483648 > 0 → false
      pollAck.Set();      // 不执行！
  → 周期轮询读的应答永远不会 Set pollAck
  → SendLoop 每轮都超时
  → 周期轮询功能完全失效

3.3 溢出触发时间估算
--------------------------------------------------------------------------------
  9600bps 下每轮周期 ≈ 50ms(超时) + 15ms(间隔) = 65ms
  2147483647 次循环 ≈ 2147483647 × 0.065s ≈ 139,636,437 秒 ≈ 4.4 年
  实际工控现场可能连续运行数年，4.4 年不是不可能。
  即使概率低，代码必须健壮——这是工控系统，不能赌"跑不到"。

3.4 更隐蔽的问题：溢出后 curPollSeq 在正负之间反复跳
--------------------------------------------------------------------------------
  溢出后 pollSeq 继续递增：-2147483648 → -2147483647 → ... → 0 → 1 → ...
  curPollSeq 会经历：负数(不 Set) → 0(不 Set) → 正数(Set) → ... → 再次溢出
  功能时好时坏，难以排查。


四、修复方案：用 volatile bool pollActive 替代 int 序号
================================================================================

4.1 为什么选 bool
--------------------------------------------------------------------------------
  - bool 只有 true/false 两个值，不存在溢出
  - volatile bool 读写是原子的（C# 规范保证）
  - 语义清晰：true=有活跃请求，false=已超时/无请求
  - 不需要区分"哪个请求"（Modbus RTU 应答不带请求序号，无法精确匹配）
    只需要知道"有没有活跃请求"即可阻断迟到应答

4.2 修复内容
--------------------------------------------------------------------------------
  删除：
    static int pollSeq = 0;
    static volatile int curPollSeq = 0;

  新增：
    static volatile bool pollActive = false;

  SendLoop 发请求前：
    原：int seq = Interlocked.Increment(ref pollSeq); curPollSeq = seq;
    新：pollActive = true;

  SendLoop 超时后：
    原：curPollSeq = -1;
    新：pollActive = false;

  Handle 中所有 curPollSeq > 0 判断：
    原：if (curPollSeq > 0) pollAck.Set();
    新：if (pollActive) pollAck.Set();


五、修复后的正确性论证
================================================================================

5.1 无溢出风险
--------------------------------------------------------------------------------
  bool 只有 true/false，赋值不会产生第三个值，永远不可能溢出。
  程序运行 100 年也不会出问题。

5.2 竞态窗口仍被消除
--------------------------------------------------------------------------------
  pollActive 是单变量，volatile 保证原子读写和跨线程可见性。
  超时后 pollActive=false 是一步操作，无窗口。
  迟到应答到达时读 pollActive 必定是 false → 不 Set pollAck。

5.3 所有时序仍安全（与上一轮分析一致）
--------------------------------------------------------------------------------
  时序1：Handle 读 curSlave(旧值) → SendLoop 置 pollActive=false →
         Handle 校验通过 → Handle 检查 pollActive(false) → 不 Set → 安全
  时序2：Handle 读 curSlave(旧值) → Handle 校验通过 → Handle 检查 pollActive(true) →
         Set pollAck → SendLoop 置 pollActive=false → pollAck.Reset() → 灯灭 → 安全


六、为什么不用 long 替代 int
================================================================================
  long 溢出时间 ≈ 9.2e18 次循环 × 0.065s ≈ 6e17 秒 ≈ 190 亿年
  实际不可能溢出，但：
  - long 在 32 位平台上读写非原子（需要 Interlocked.Read）
  - 用 long 解决溢出是"把问题推到更远"，不是"消除问题"
  - bool 直接消除溢出可能性，更干净


七、总结
================================================================================
用户精准地指出了 int 序号的溢出风险：pollSeq 到 int.MaxValue 后 +1 变负数，
curPollSeq > 0 判断反转，周期轮询读功能失效。

修复：用 volatile bool pollActive 替代 int 序号。
bool 无溢出，语义清晰，单变量原子读写，竞态窗口仍被消除。
编译通过，零错误。
