一、用户问题
================================================================================
else if (pollActive) pollAck.Set();
这个 pollActive 在接收线程不用局部变量以及线程栈的原因是啥？
为啥这样设计？


二、结论：两种设计对应两种不同的安全需求
================================================================================
pollActive 直接读字段（不拷贝局部变量）是正确的设计。
activeWrite/activeRead 用局部变量拷贝也是正确的设计。
原因：两者要防范的竞态不同——
  - activeWrite/activeRead 是引用类型，要防范"读到 null 后被别人改"的空引用风险
  - pollActive 是值类型(bool)，要防范"读到旧值导致误 Set"，直接读字段拿最新值最安全


三、对比：activeWrite/activeRead 为什么用局部变量
================================================================================

3.1 代码
--------------------------------------------------------------------------------
  var aw = activeWrite;   // 拷贝到局部变量
  if (aw != null) { aw.AckOk = false; aw.Ack.Set(); }

3.2 为什么拷贝？
--------------------------------------------------------------------------------
  activeWrite 是 volatile 引用类型（class WriteRequest）。
  两次读 activeWrite 可能拿到不同的值：
    if (activeWrite != null)          // 第一次读：非 null
        activeWrite.AckOk = false;    // 第二次读：可能已被置 null！→ NullReferenceException
  拷贝到局部变量 aw 后，aw 不会变：
    var aw = activeWrite;             // 一次性读
    if (aw != null)                   // 判断 aw（不变）
        aw.AckOk = false;             // 用 aw（不变）→ 安全

3.3 核心风险：空引用异常
--------------------------------------------------------------------------------
  引用类型不拷贝的后果是"崩溃"（NullReferenceException）。
  拷贝是为了"快照"——拿到某一时刻的引用，之后即使 activeWrite 被置 null，
  aw 仍指向那个对象，可以安全访问。


四、pollActive 为什么直接读字段
================================================================================

4.1 代码
--------------------------------------------------------------------------------
  else if (pollActive) pollAck.Set();   // 直接读字段

4.2 pollActive 是值类型(bool)，不是引用
--------------------------------------------------------------------------------
  static volatile bool pollActive;
  bool 只有两个值：true/false。
  读 pollActive 拿到 true 或 false，不存在"空引用"风险。
  if (pollActive) 判断的是值，不是引用，不会 NullReferenceException。

4.3 直接读字段拿"最新值"正是我们想要的
--------------------------------------------------------------------------------
  pollActive 的语义：此刻是否有活跃的周期轮询请求。
  Handle 处理应答时，想知道"现在"是否活跃：
    - true：有活跃请求 → Set pollAck
    - false：已超时/无请求 → 不 Set
  直接读字段拿的是"读取那一刻的最新值"（volatile 保证），这正是判断依据。

  如果拷贝到局部变量：
    bool active = pollActive;   // 拷贝
    // ... SendLoop 此刻可能把 pollActive 从 true 改成 false（超时了）
    if (active) pollAck.Set();  // active 还是 true（旧值）→ 误 Set！
  拷贝反而可能拿到"过期的旧值"，导致在已超时的情况下还 Set。

4.4 核心区别：我们要"最新值"还是"快照"
--------------------------------------------------------------------------------
  activeWrite/activeRead：要"快照"——拿到一个稳定的引用，防止中途变 null
  pollActive：要"最新值"——想知道此刻是否活跃，拷贝反而拿到旧值

  ★ 引用类型拷贝：防 null，拿快照
  ★ 值类型直接读：拿最新，防过期


五、pollActive 直接读的安全性分析
================================================================================

5.1 读到 true 的情况
--------------------------------------------------------------------------------
  pollActive==true 说明"读取那一刻有活跃请求"。
  Set pollAck 是正确的——这个应答应该通知 SendLoop。
  即使 Set 之后 SendLoop 立刻超时把 pollActive 置 false，
  pollAck 已经 Set 了，SendLoop 的 pollAck.Reset() 会关掉它（时序安全，前几轮已论证）。

5.2 读到 false 的情况
--------------------------------------------------------------------------------
  pollActive==false 说明"读取那一刻已超时/无请求"。
  不 Set pollAck 是正确的——没人等这个应答，丢弃。
  即使 false 是"刚被超时置的"，也正确——超时了就不该再 Set。

5.3 volatile 保证不会读到"半真半假"
--------------------------------------------------------------------------------
  bool 在 C# 中原子读写（规范保证），volatile 进一步保证可见性。
  要么读到 true，要么读到 false，不会读到中间态。


六、如果 pollActive 拷贝到局部变量会怎样
================================================================================

6.1 代码
--------------------------------------------------------------------------------
  bool active = pollActive;        // 拷贝
  // ★ 窗口：SendLoop 此刻超时，pollActive 从 true 变 false
  if (active) pollAck.Set();       // active 还是 true（旧值）→ Set！

6.2 后果
--------------------------------------------------------------------------------
  SendLoop 已超时（pollActive=false, pollAck.Reset()），
  但 Handle 用旧值 active=true 还是 Set 了 pollAck。
  如果 Set 在 Reset 之后 → 灯亮 → 下一轮 WaitOne 误判成功。
  ★ 拷贝反而引入了"用过期旧值判断"的风险。

6.3 对比直接读
--------------------------------------------------------------------------------
  if (pollActive) pollAck.Set();   // 直接读
  // 读到 false（SendLoop 已超时）→ 不 Set → 安全
  直接读拿最新值，反而更安全。


七、为什么 activeWrite 不担心"读到旧值"
================================================================================

7.1 activeWrite 的"旧值"是旧请求对象
--------------------------------------------------------------------------------
  var aw = activeWrite;   // 拿到旧请求对象
  if (aw != null) aw.Ack.Set();   // Set 旧请求的 Ack
  即使 aw 是"已被 ExecuteWrite finally 置 null 之前的旧请求"，
  Set 旧请求的 Ack 也无害——ExecuteWrite 已经 return 了，没人等这个 Ack。
  旧请求的 Ack 被 Set，但旧请求的 WaitOne 已经过去了（超时或成功返回），Set 无副作用。

7.2 activeWrite 的风险是 null 不是"旧值"
--------------------------------------------------------------------------------
  如果不拷贝，两次读 activeWrite：
    if (activeWrite != null)       // 非 null
      activeWrite.Ack.Set();       // 可能变 null → 崩溃
  风险是 NullReferenceException（崩溃），不是"逻辑错误"。
  拷贝消除崩溃风险，"旧值"无副作用，所以拷贝是对的。

7.3 pollActive 的风险是"旧值"不是 null
--------------------------------------------------------------------------------
  bool 不会 null，没有崩溃风险。
  但"旧值"（true）会导致误 Set（逻辑错误）。
  直接读拿最新值，消除"旧值"风险。


八、总结：两种设计的本质区别
================================================================================

  ┌─────────────────┬──────────────────────────┬──────────────────────────┐
  │                 │ activeWrite/activeRead   │ pollActive               │
  │                 │ (引用类型 class)         │ (值类型 bool)            │
  ├─────────────────┼──────────────────────────┼──────────────────────────┤
  │ 类型            │ 引用(class)              │ 值(bool)                 │
  │ 空引用风险      │ 有(NullReferenceException)│ 无(bool 不会 null)       │
  │ 旧值风险        │ 无副作用(Set 旧 Ack 无害) │ 有(误 Set pollAck)       │
  │ 拷贝目的        │ 防空引用(拿快照)         │ 不需要(无空引用)         │
  │ 直接读目的      │ 不安全(可能变 null)      │ 拿最新值(防旧值误判)     │
  │ 最终选择        │ 拷贝到局部变量           │ 直接读字段               │
  └─────────────────┴──────────────────────────┴──────────────────────────┘

  本质：引用类型拷贝防 null，值类型直接读防过期。
  两种设计都是正确的，针对各自的风险。
