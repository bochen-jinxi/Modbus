Program.cs 多按钮同时操作 改造分析报告
============================================================
日期：2026-11-02
文件：F:\chenbo\Program.cs

------------------------------------------------------------
一、问题：原代码只能一个按钮开到位
------------------------------------------------------------

原写操作路径：CmdLoop → SwitchOn/Off → WriteSingleCoil
WriteSingleCoil 是同步阻塞调用：发写帧 → writeDone.WaitOne 等回显 → 失败重试。

三重瓶颈导致"一次只一个写"：

1. 全局单例写信号（原 Program.cs:24-30）
   static readonly AutoResetEvent writeDone = new AutoResetEvent(false);
   static volatile byte writeSlave;
   static volatile bool writeOk;
   static volatile byte[] curWriteFrame;

   两个写并发时：
   - 后发的写覆盖前一个的 curWriteFrame，前一个的回显比对失败被当"旧应答"忽略
     （Program.cs:367-374 整帧比对），前一个写超时。
   - writeDone.Set() 可能唤醒正在等另一个从站的写线程，造成错配
     （B 以为成功，实际 A 才成功）。

2. CmdLoop 单线程阻塞（原 Program.cs:514-542）
   SwitchOn/Off 同步阻塞等回显，用户输完一条 "on 1 0" 要等 50ms+ 才能输下一条，
   无法"同时按多个按钮"。

3. RS485 半双工总线
   即使逻辑上允许多线程并发写，物理总线同一时刻只能有一帧在传，
   两个写帧同时 sp.Write 会帧碰撞。

------------------------------------------------------------
二、结论：必须改造
------------------------------------------------------------

不改造无法支持工控现场多按钮同时操作。

------------------------------------------------------------
三、改造方案（最小改动，符合工控现场实际）
------------------------------------------------------------

"多按钮同时操作" = 多个写请求并发提交、排队串行执行，
每个独立等自己的回显、独立返回成功/失败。
不是真的让两帧同时在总线上打架。

需要改的点：
1. 写请求队列：CmdLoop（或多个命令源）把写请求投递到队列，立即返回"已提交"。
2. 专用写线程串行从队列取请求、发帧、等回显，保证总线一次一帧。
3. 每个写请求独立的应答信号（不再共享全局 writeDone/writeOk/curWriteFrame），
   避免并发错配。
4. Handle 按"当前写线程正在处理的请求"分发回显，而不是全局单例。

------------------------------------------------------------
四、具体改动（F:\chenbo\Program.cs）
------------------------------------------------------------

【1. 字段定义区（约 23-44 行）】

新增 WriteRequest 类（每个按钮一次写就是一个 WriteRequest，自带独立应答信号）：

    class WriteRequest
    {
        public byte Slave;
        public ushort Addr;
        public bool On;
        public byte[] Frame;                 // 完整发送帧（含CRC），用于回显比对
        // Ack：Handle 收到 0x05 回显时 Set，ExecuteWrite 等它（每轮重试前 Reset）
        public readonly AutoResetEvent Ack = new AutoResetEvent(false);
        public bool AckOk;                   // 一次回显的结果
        // Completed：WriteLoop 执行完整个请求（含重试）后 Set，WriteSingleCoil 等它
        public readonly ManualResetEventSlim Completed = new ManualResetEventSlim(false);
        public bool Result;                  // 最终结果
    }

新增写请求队列 + 活跃请求指针：

    static readonly ConcurrentQueue<WriteRequest> writeQueue = new ConcurrentQueue<WriteRequest>();
    static volatile WriteRequest activeWrite;

删除原全局单例：
    - static readonly AutoResetEvent writeDone
    - static volatile byte writeSlave
    - static volatile bool writeOk
    - static volatile byte[] curWriteFrame

using 新增：
    using System.Collections.Concurrent;


【2. Main（约 101-149 行）】

启动写线程：
    Thread wx = new Thread(WriteLoop) { IsBackground = true };
    wx.Start();

参数模式也启动写线程：

    pWx.Start();

【4. WriteSingleCoil / WriteLoop / ExecuteWrite（约 478-582 行）】

WriteSingleCoil 改为"投递请求 + 阻塞等 Completed"：

    static bool WriteSingleCoil(byte slave, ushort addr, bool on)
    {
        byte[] req = { slave, 0x05, (byte)(addr >> 8), (byte)(addr & 0xFF), (byte)(on ? 0xFF : 0x00), 0x00 };
        byte[] frame = Crc(req);
        var wr = new WriteRequest { Slave = slave, Addr = addr, On = on, Frame = frame };
        writeQueue.Enqueue(wr);
        int waitMs = WriteRetry * (TimeoutMs + IntervalMs + 50) + 500;
        if (!wr.Completed.Wait(waitMs))
        {
            Console.WriteLine($"[写失败·从站{slave:X2}] 排队执行超时");
            return false;
        }
        return wr.Result;
    }

WriteLoop 写线程串行消费队列：

    static void WriteLoop()
    {
        while (running)
        {
            if (!writeQueue.TryDequeue(out var wr))
            {
                Thread.Sleep(5);
                continue;
            }
            bool ok = ExecuteWrite(wr);
            wr.Result = ok;
            wr.Completed.Set();
        }
    }

ExecuteWrite 实际执行（含重试），由 WriteLoop 串行调用：

    static bool ExecuteWrite(WriteRequest wr)
    {
        for (int attempt = 1; attempt <= WriteRetry; attempt++)
        {
            lock (io) { if (sp.IsOpen) sp.DiscardInBuffer(); }
            lock (gate) { buf.Clear(); }
            wr.Ack.Reset();
            activeWrite = wr;                    // 设为活跃请求

            // 发送
            lock (io) { if (!sp.IsOpen) return false; sp.Write(frame, 0, frame.Length); }

            if (wr.Ack.WaitOne(TimeoutMs))
            {
                if (wr.AckOk) return true;      // 成功回显
            }
            Thread.Sleep(IntervalMs);
        }
        return false;
    }


【5. CmdLoop / ParseAndSubmit（约 590-660 行）—— 支持并发提交】

CmdLoop 支持一行多命令（; 分隔），模拟多个按钮同时按下：

    string[] cmds = line.Split(new[] { ';' }, StringSplitOptions.RemoveEmptyEntries);
    foreach (var one in cmds) ParseAndSubmit(one.Trim());

ParseAndSubmit 异步投递（默认）或同步等结果（sync 前缀）：

    - 异步：writeQueue.Enqueue(wr); 立即返回"已提交"；
            ThreadPool.QueueUserWorkItem 后台等 Completed 打印结果。
    - 同步：WriteSingleCoil 阻塞等结果。

五、改造前后对比
------------------------------------------------------------

| 改造点     | 原来                          | 现在                                    |
|-----------|-------------------------------|----------------------------------------|
| 写信号     | 全局单例 writeDone/writeOk 等 | 每请求独立 WriteRequest（Ack+Completed） |
| 写执行     | WriteSingleCoil 直接发+等     | 投递队列 + WriteLoop 串行 + ExecuteWrite |
| 回显分发   | Handle 无差别 writeDone.Set() | Handle 按 activeWrite 分发到 aw.Ack     |

------------------------------------------------------------
八、线程安全分析
------------------------------------------------------------

1. writeQueue（ConcurrentQueue）：多线程并发 Enqueue 安全，无锁。
2. activeWrite（volatile）：写线程串行赋值，接收线程读，单写多读，volatile 保证可见性。
3. 每个 WriteRequest 的 Ack/Completed：只有 WriteLoop 和 Handle 会 Set，
   WriteSingleCoil/后台结果线程只 Wait，无竞争。
4. sp.Write 在 lock(io) 内，与 OnData 的 sp.Read 互斥，不会读写交叉。
5. RS485 总线：WriteLoop 串行执行，同一时刻只有一个 activeWrite，保证一次一帧。
