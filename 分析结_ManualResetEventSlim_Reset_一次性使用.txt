ManualResetEventSlim.Completed 为什么不调用Reset()？
================================================================================
分析时间：2026-11-09

分析问题：wr.Completed（ManualResetEventSlim）为什么不Reset()，是否因为只使用一次？

================================================================================
一、直接回答
================================================================================

是的。wr.Completed只使用一次（一次Set + 一次Wait），用完即弃，
每次WriteSingleCoil都new一个全新的WriteRequest（Completed初始为false），
所以不需要Reset()。

================================================================================
二、ManualResetEventSlim vs AutoResetEvent 的Reset()语义
================================================================================

【ManualResetEventSlim】
- Set()后：信号保持"亮"状态，所有WaitOne都会立即返回，直到手动Reset()
- Reset()后：信号回到"灭"状态，WaitOne会阻塞
- 适用场景：需要"通知所有人"且信号持续保持的场景
- 如果不复用对象，不需要Reset()

【AutoResetEvent】
- Set()后：信号"亮"一瞬间，一个WaitOne返回后自动Reset()
- 适用场景：需要"通知一个人"且信号自动复位的场景
- 每次WaitOne前需要Reset()吗？不需要，AutoResetEvent自动复位

【当前代码中的使用】

│ 信号                     │ 类型                  │ 使用模式               │
├──────────────────────────┼───────────────────────┼────────────────────────┤
│ wr.Completed             │ ManualResetEventSlim  │ 一次Set + 一次Wait     │
│ wr.Ack                   │ AutoResetEvent        │ 多次Set + 多次Wait     │
│ pollAck                  │ AutoResetEvent        │ 多次Set + 多次Wait     │

================================================================================

================================================================================
四、为什么不需要Reset()？
================================================================================

【Reset()的作用】
将ManualResetEventSlim从"亮"重置为"灭"，以便下次WaitOne能再次阻塞。

【不需要Reset()的原因】

1. 对象只使用一次：
   - Completed: false → Wait阻塞 → Set → Wait返回 → 对象被GC回收
   - 没有第二次Wait，所以不需要Reset回false

2. 每次都是新对象：
   - WriteSingleCoil每次调用都new WriteRequest()
   - 新对象的Completed初始就是false
   - 不存在"上一次Set后信号残留"的问题

3. 如果复用对象才需要Reset()：
   - 假设WriteRequest被对象池复用：
     wr.Completed.Set() → 回收 → 下次取出 → wr.Completed.Reset() → Wait
   - 但当前代码不复用，每次new新对象

五、对比：wr.Ack 为什么需要Reset()？
================================================================================

【wr.Ack的生命周期】

ExecuteWrite（重试循环内）
    │
    │ 第1次尝试：
    │   wr.Ack.Reset()  ← 必须Reset！因为上一轮可能Set过
    │   SendFrame()
    │   wr.Ack.WaitOne(TimeoutMs) ←阻塞
    │   超时 → 继续重试
    │
    │ 第2次尝试：
    │   wr.Ack.Reset()  ← 必须Reset！清除上一轮的残留信号
    │   SendFrame()
    │   wr.Ack.WaitOne(TimeoutMs) ←阻塞
    │   收到回显 → Ack.Set() → WaitOne返回
    │
    │ 第3次尝试（如果需要）：
    │   wr.Ack.Reset()  ← 同上
    │   ...

【为什么Ack需要Reset而Completed不需要】

六、ThreadPool.QueueUserWorkItem 与信号量的关系
================================================================================

【用户提到的ThreadPool.QueueUserWorkItem】
位置：EnqueueReadTasks方法（第957行）

ThreadPool.QueueUserWorkItem(_ =>
{
    Thread.Sleep(delay);       // 延迟等设备数据就绪
    readQueue.Enqueue(rr);     // 投递读任务到队列
});

【这个ThreadPool回调里没有使用任何ManualResetEventSlim】
- 它只是Thread.Sleep + readQueue.Enqueue
- 不涉及Completed或Ack的任何操作
- rr（ReadRequest）的Completed字段虽然定义了，但从未被使用（死代码）

【ReadRequest.Completed 是死代码】
ReadRequest类定义了Completed字段（第72行）：
  public readonly ManualResetEventSlim Completed = new ManualResetEventSlim(false);

但在整个代码中，ReadRequest.Completed从未被Set或Wait：
- ExecuteRead只使用rr.Ack（AutoResetEvent）
- SendLoop调用ExecuteRead后直接继续，不等Completed
- 没有任何代码调用rr.Completed.Set()或rr.Completed.Wait()

结论：ReadRequest.Completed是死代码，可以删除。

七、反例验证
================================================================================

【反例1：如果Completed需要复用但不Reset()】
假设WriteRequest被对象池复用：
  第1次：Completed.Set() → Wait返回 → 对象回池
  第2次：从池中取出 → Completed.Wait() → 立即返回（信号还是"亮"）
  结果：Wait不阻塞，直接返回，但Result可能是上一次的值

修复：从池中取出后必须Completed.Reset()

但当前代码不复用，所以不会出现这个问题。

【反例2：如果Completed在构造时不是false】
ManualResetEventSlim的构造函数：
  new ManualResetEventSlim(false) → 初始为false（灭）
  new ManualResetEventSlim(true)  → 初始为true（亮）

当前代码用false初始化，所以新对象的Wait会正确阻塞 ✅

如果误用true初始化：
  new WriteRequest { ... }
  → Completed初始为true（亮）
  → WriteSingleCoil的Wait立即返回
  → Result可能是默认值false
  → 误判为"写失败"

但当前代码用false初始化，不会出现这个问题 ✅

================================================================================
八、总结
================================================================================

【核心结论】
wr.Completed不调用Reset()的原因是：对象只使用一次，用完即弃，每次new新对象。

【详细原因】
1. WriteSingleCoil每次调用都new WriteRequest，Completed初始为false
2. Completed只有一次Set（WriteLoop完成后）和一次Wait（WriteSingleCoil等待）
3. 用完后wr被GC回收，Completed也随之回收
4. 不存在复用场景，不需要Reset()

【对比Ack】
wr.Ack需要Reset()，因为同一wr在重试循环中被多次使用，
上一轮的Set可能残留信号，需要Reset清除。

【额外发现】
ReadRequest.Completed是死代码，从未被Set或Wait，可以删除。
