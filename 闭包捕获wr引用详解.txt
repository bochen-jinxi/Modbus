============================================================
闭包捕获 wr 引用 详解
============================================================
日期：2026-11-02
相关代码：F:\chenbo\Program.cs 的 ParseAndSubmit 方法

------------------------------------------------------------
一、问题
------------------------------------------------------------

ThreadPool.QueueUserWorkItem 的 lambda 捕获了局部变量 wr，
这个捕获到的是 wr 的引用吗？为什么不会取到别的 wr？

------------------------------------------------------------
二、结论
------------------------------------------------------------

闭包捕获局部变量 wr，捕获的就是 wr 这个变量本身（变量槽）。
而 wr 是引用类型变量，变量槽里存的是堆上对象的指针。
所以 lambda 里的 wr.Completed 访问的是堆上同一个对象，
跟外层 new 出来的是同一个实例。

------------------------------------------------------------
三、C# 闭包捕获语义
------------------------------------------------------------

代码：
    var wr = new WriteRequest { ... };   // wr 局部变量 → 指向堆上对象 0x1000
    writeQueue.Enqueue(wr);

    ThreadPool.QueueUserWorkItem(_ =>
    {
        wr.Completed.Wait(waitMs);   // ← 这个 wr 是捕获的外层变量
    });

两种捕获语义对比：

| 捕获方式              | lambda 里的 wr 是       | 改 lambda 里 wr 会怎样      |
|----------------------|------------------------|----------------------------|
| 捕获变量本身（C#默认）| 外层 wr 这个变量槽      | 外层 wr 也变（同一个槽）    |
| 捕获变量的值          | 一份拷贝               | 外层不变                    |

C# 闭包默认"捕获变量本身"（不像 C++ 要显式写 & 或 =）。

------------------------------------------------------------
四、引用类型变量 = 变量槽存指针
------------------------------------------------------------

内存布局：
    栈上：wr 变量槽 → 存着指针 0x1000
    堆上：0x1000 处是 WriteRequest 对象（含 Completed、Result 等）

闭包捕获的是"栈上 wr 这个变量槽"。
lambda 执行时读 wr，读到槽里的值 0x1000，然后访问 0x1000.Completed。
所以 lambda 里的 wr.Completed 实际是 0x1000.Completed——
跟外层 new 出来的是堆上同一个对象。

------------------------------------------------------------
五、验证：同一个对象
------------------------------------------------------------

    var wr = new WriteRequest { Slave = 1 };
    Console.WriteLine($"外层 wr 哈希: {wr.GetHashCode()}");   // 假设 12345

    ThreadPool.QueueUserWorkItem(_ =>
    {
        Console.WriteLine($"lambda wr 哈希: {wr.GetHashCode()}");  // 也是 12345
    });

两个 GetHashCode() 相同 → 同一个对象实例 → 同一个 Completed 信号。

------------------------------------------------------------
六、为什么不会取到别的 wr
------------------------------------------------------------

lambda 捕获的是"定义时那个外层变量 wr"，不是"队列里随便一个"。
即使队列里有 100 个 wr，这个 lambda 也只认它被创建时捕获的那个。

    循环第1次：wr = new WriteRequest @ 0x1000
      lambda1 捕获 wr（此时 wr 槽 = 0x1000）
      → lambda1 永远等 0x1000.Completed

    循环第2次：wr = new WriteRequest @ 0x2000
      lambda2 捕获 wr（此时 wr 槽 = 0x2000）
      → lambda2 永远等 0x2000.Completed

每次 new 产生新对象，wr 槽更新为新指针，新 lambda 捕获新值。
老 lambda 已经捕获了老指针，不受影响。

------------------------------------------------------------
七、容易踩的坑（本代码没踩）
------------------------------------------------------------

❌ 错误写法（循环变量复用同一槽）：
    WriteRequest wr;
    foreach (var cmd in cmds)
    {
        wr = new WriteRequest { ... };   // 复用同一个 wr 槽
        ThreadPool.QueueUserWorkItem(_ => wr.Completed.Wait());
        // 所有 lambda 捕获同一个槽，执行时都读到最后一次的 0x2000 → 全错
    }

✓ 正确写法（本代码的写法）：
    foreach (var one in cmds)
    {
        ParseAndSubmit(one);   // 每次调用 ParseAndSubmit，里面 var wr 是新局部变量
    }
    // ParseAndSubmit 内：
    var wr = new WriteRequest { ... };   // 每次调用是新栈帧，新 wr 槽
    ThreadPool.QueueUserWorkItem(_ => wr.Completed.Wait());  // 捕获这次调用的 wr

关键：ParseAndSubmit 是独立方法，每次调用有独立的栈帧，
var wr 是这次调用自己的局部变量，lambda 捕获的就是这个独立的 wr。
不会串。

------------------------------------------------------------
八、完整链路：同一个 wr 引用如何从创建传到 Set
------------------------------------------------------------

假设 new 出的 wr 在堆上地址 0x1000：

1. ParseAndSubmit:
   wr (局部变量) → 0x1000
   writeQueue.Enqueue(wr)  → 队列存 0x1000
   后台线程A 捕获 wr → 等 0x1000.Completed

2. WriteLoop:
   TryDequeue(out var wr) → wr = 0x1000   ← 同一个地址
   ExecuteWrite(wr)       → 传 0x1000
   wr.Completed.Set()     → Set 0x1000.Completed → 唤醒后台线程A

3. ExecuteWrite:
   参数 wr = 0x1000
   activeWrite = wr → activeWrite = 0x1000
   Handle 收到回显 → activeWrite.Ack.Set() → Set 0x1000.Ack

全链路都是 0x1000 这一个对象。

------------------------------------------------------------
九、关键 C# 语义清单
------------------------------------------------------------

1. WriteRequest 是 class（引用类型），不是 struct。
   队列里存引用（指针），不是值拷贝。

2. TryDequeue(out var wr) 把队列头部的引用赋给 wr，
   这个引用指向的就是当初 Enqueue 进去的那个对象。

3. ExecuteWrite(WriteRequest wr) 参数是引用传递（class 默认），
   函数内的 wr 和外面是同一个对象。

4. wr.Completed 是 readonly 字段，每个 WriteRequest 实例有自己独立的 Completed，
   Set() 只影响这一个。

5. 闭包捕获局部变量本身（变量槽），引用类型变量槽存的是指针，
   所以 lambda 里的 wr 和外层 wr 指向堆上同一个对象。

6. ParseAndSubmit 是独立方法，每次调用新栈帧，var wr 是新局部变量，
   不会跨调用串。

------------------------------------------------------------
十、一句话总结
------------------------------------------------------------

闭包捕获局部变量 wr，捕获的是变量槽；
wr 是引用类型，槽里存的是堆上对象的指针；
所以 lambda 里的 wr 和外层 new 出来的是堆上同一个对象。
ParseAndSubmit 每次调用有独立栈帧，var wr 互不干扰，
每个 lambda 只等自己那个 wr.Completed，不会错取。
