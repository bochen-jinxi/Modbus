volatile 引用类型字段 vs 非 volatile 引用类型字段
================================================

一、核心区别
volatile 对引用类型字段的作用：
  保证该**引用**的读写可见性 + 禁止重排。
  不保护引用指向的**对象内部状态**。

非 volatile 引用类型字段：
  引用的读写不保证可见性（可能读到旧引用）。
  同样不保护对象内部状态。

区别只在"引用本身"，不在"对象内容"。


二、具体场景：多线程读写字段的引用

场景1：一个线程写引用，一个线程读引用
  volatile SerialPort sp;
  线程A：sp = new SerialPort("COM4", ...);
  线程B：if (sp != null) sp.Open();

  有 volatile：线程A写 sp 后，线程B立刻看到新引用，不会看到 null 或旧引用。
  无 volatile：线程B可能永远看不到新引用（CPU 缓存未刷），一直读到 null。
  ★ 这是 volatile 对引用类型的真正作用：保证引用可见性。

场景2：一个线程写引用，多个线程读引用
  同上，volatile 保证所有读线程看到最新引用。

场景3：多个线程都写引用（切换不同对象）
  volatile 保证每次写后读线程看到最新引用。
  但若两个线程同时写不同引用，volatile 不保证"谁最后写"的原子性——
  最终 sp 指向哪个不确定，但不会损坏引用本身（引用读写是原子的）。

场景4：通过引用读写对象内部状态（多线程共用的同一对象）
  sp.Open() / sp.Write() / sp.Read() / sp.DiscardInBuffer()
  这些是**通过引用访问对象内部状态**。
  volatile 对这部分完全不管！
  必须靠 lock(io) 互斥保护。

  所以：sp 有 volatile 也不能替代 lock(io)。
  没有 volatile 也不妨碍 lock(io) 保护对象内部。
  volatile 和 lock 保护的是不同层面。


三、volatile 对引用类型做了什么
  1. 单步读/写引用是原子的（引用=指针，32位/64位对齐读写）。
  2. volatile 保证写引用后立刻对其他线程可见（插入内存屏障）。
  3. volatile 禁止编译器/CPU 对该引用的读写重排。

  不做什么：
  1. 不保护对象内部状态（那是 lock 的事）。
  2. 不保证"读对象成员"的原子性（如 sp.BytesToRead 可能读到旧值）。
  3. 不保证"通过引用调方法"的线程安全（sp.Write 不是线程安全）。


四、对比表
  特性                          volatile 引用    非 volatile 引用
  引用读写原子性                是（对齐）       是（对齐）
  引用写后对其他线程可见        立刻可见         可能延迟或永远不可见
  禁止引用读写重排              是               否
  保护对象内部状态              否               否
  保护通过引用的方法调用        否               否

  可见性是唯一区别！原子性两者都有。


五、为什么 sp 不需要 volatile（本项目）
  1. sp 只在 Main 启动时赋值一次，之后不再改（写一次后只读）。
  2. Thread.Start() 自带内存屏障，主线程在 Start 前的写对新线程可见。
  3. 所以即使不加 volatile，子线程启动时也必定看到 sp 已赋值。
  4. 没有"运行中切换引用"的场景，volatile 的"引用可见性"优势无用武之地。

  如果 sp 会被某个线程中途重新赋值（如 sp = new SerialPort(...) 换端口），
  且其他线程要读这个新引用，那才需要 volatile。


六、什么时候引用类型字段需要 volatile
  需要同时满足：
  1. 运行中会切换引用（不是只赋值一次）。
  2. 其他线程要读到最新引用。
  3. 不用 lock 保护引用切换（lock 也能保证可见性，但更重）。

  例：
    volatile ILogger logger = new ConsoleLogger();
    线程A：logger = new FileLogger(...);  // 切换日志输出目标
    线程B：logger.Write(msg);             // 读到最新 logger
    有 volatile：线程B 立刻看到新 logger。
    无 volatile：线程B 可能一直用旧的 ConsoleLogger。

  注意：即使 logger 有 volatile，logger.Write 仍可能多线程并发调用不安全——
  那是 ILogger 实现的事，volatile 不管。


七、口诀
volatile 管引用可见，不管对象内部；
引用读写都原子，可见性是唯一区别。
写一次不用 volatile，Thread.Start 有屏障；
运行中切引用要 volatile，读线程才能看到新。
对象状态要 lock，引用切换要 volatile；
两个层面各管各，混淆就会出漏洞。


八、涉及本项目
  static SerialPort sp;  // 无 volatile，只赋值一次，Thread.Start 屏障可见
  lock(io) { sp.Write(); }  // 锁保护对象内部状态，不是 volatile 的事
  即使 sp 加了 volatile，lock(io) 也不能省——保护的是不同层面。
