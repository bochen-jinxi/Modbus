三、重构后：提取 SendFrame 方法
================================================================================

3.1 新增方法（ClearRxState 之后）
--------------------------------------------------------------------------------
    // ★ 发送一帧到串口。统一 IsOpen 检查 + lock(io) 保护。
    //   返回 true=发送成功，false=串口已关闭。
    //   ★ 不吞异常：sp.Write 可能抛异常（写超时/串口故障），调用方 try-catch 处理。
    //   这样调用方可以保留自己的异常日志格式（发送异常/写异常/读异常）和重试逻辑。
    static bool SendFrame(byte[] frame)
    {
        lock (io)
        {
            if (!sp.IsOpen) return false;
            sp.Write(frame, 0, frame.Length);
        }
        return true;
    }

3.2 SendLoop 替换

    }

四、设计决策
================================================================================

4.1 为什么 SendFrame 不吞异常
--------------------------------------------------------------------------------
    三处调用方的异常处理不同：
      - SendLoop：打印"发送异常"，continue 跳过本轮
      - ExecuteWrite：打印"写异常"，sendFailed=true 触发重试
      - ExecuteRead：打印"读异常"，sendFailed=true 触发重试
    如果 SendFrame 内部 try-catch 吞掉异常，调用方无法区分"串口关闭"和"发送异常"。
    不吞异常 → sp.Write 抛异常直接传播 → 调用方 try-catch 各自处理。
    返回值只表示"串口是否打开"，异常由调用方处理。

4.2 为什么返回 bool 而不是 void
--------------------------------------------------------------------------------
    原代码有 if(!sp.IsOpen) break/return 的检查，串口关闭时需要通知调用方。
    返回 false 表示"串口已关闭"，调用方据此 break/return。
    返回 true 表示"发送成功（至少没因 IsOpen 失败）"。

4.3 为什么不把 try-catch 放进 SendFrame
--------------------------------------------------------------------------------
    放进去的话，SendFrame 需要返回三态（成功/串口关闭/异常），
    调用方还要根据三态做不同处理（break/return/重试），反而更复杂。
    不放进去 → SendFrame 只管"发"，异常由调用方处理，职责清晰。


五、重构收益
================================================================================

5.1 消除重复
--------------------------------------------------------------------------------
    三处相同的 lock(io){ if(!sp.IsOpen)...; sp.Write(...) } → 一处方法 + 三处一行调用

5.2 统一 IsOpen 检查
--------------------------------------------------------------------------------
    原来三处各自写 if(!sp.IsOpen)，现在统一在 SendFrame 内。
    不会因为某处漏写 IsOpen 检查导致对已关闭串口 Write 抛异常。

5.3 统一 lock(io) 保护
--------------------------------------------------------------------------------
    三处都用同一个方法，lock(io) 必然一致，不会因为某处漏锁导致与 OnData 竞争。

5.4 意图清晰
--------------------------------------------------------------------------------
    SendFrame(frame) 名字直接表达"发送一帧"的意图。
