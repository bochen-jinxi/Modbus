【三、推送失败原因分析 (关键)】
------------------------------------------------------------
尝试了 4 种方式，全部失败，根因明确:

方式 1: HTTPS 直连 github.com:443
  结果: Connection was reset / Failed to connect port 443
  原因: 当前网络环境对 github.com:443 进行了拦截/重置。
        ping 可达 (78ms)，但 TCP 443 端口无法建立连接。
        典型见于公司防火墙/校园网/地区网络策略。

方式 2: SSH 直连 git@github.com:22
  结果: Host key verification failed → Permission denied (publickey)
  原因: 22 端口可能被拦截，且本地 SSH 公钥未在 GitHub 注册。

方式 3: SSH 走 443 端口 (ssh.github.com:443)
  结果: 网络连通，但 Permission denied (publickey)
  原因: 网络通了，但本地 SSH 公钥未添加到 bochen-jinxi 账户。
        本地公钥: ssh-ed25519 ...test (注释为 "test")
        该公钥显然不是绑定到 bochen-jinxi 账户的密钥。

方式 4: HTTPS 加大缓冲重试
  结果: 同方式 1，443 端口不通。

【四、根本结论】
------------------------------------------------------------
A. 网络层面:
   github.com:443 (HTTPS) 在当前网络下被阻断。
   ssh.github.com:443 (SSH over 443) 网络可达。

B. 认证层面:
   本地 SSH 公钥 (id_ed25519, 注释 test) 未在
   bochen-jinji 的 GitHub 账户中注册，
   因此即使网络通了也无法通过公钥认证。

C. 要完成推送，必须同时解决网络 + 认证两个问题。

【五、解决方案 (按推荐顺序)】
------------------------------------------------------------
方案 1 (推荐): 注册 SSH 公钥 + 走 443 端口
  步骤:
    1) 复制下面这行公钥:
       ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIDe6p7BRSVtq39dRTx/UUi2u2RxrUwunu1ugZlr6mqSI test
    2) 登录 https://github.com/settings/keys
    3) 点击 "New SSH key"，粘贴公钥，保存
    4) 回到终端执行:
         git remote set-url origin git@github.com:bochen-jinxi/Modbus.git
         git push -u origin main
    5) 已配置 ~/.ssh/config 让 github.com 走 ssh.github.com:443，
       可绕过 22 端口封锁。
  优点: 一次配置长期有效；绕过 HTTPS 拦截。

方案 2: 使用 Personal Access Token (PAT) + HTTPS 代理
  步骤:
    1) 登录 https://github.com/settings/tokens 生成 PAT (勾选 repo)
    2) 配置 git 凭据:
         git config credential.helper store
    3) 推送时用户名填 bochen-jinxi，密码填 PAT
    4) 但当前 HTTPS 443 被拦截，需先解决网络:
       - 接入可访问 GitHub 的网络 (手机热点/VPN/代理)
       - 或配置 git http.proxy 走本地代理
  缺点: 受网络限制，可能仍无法连通。

方案 3: 切换网络环境
  步骤:
    1) 切换到可访问 github.com:443 的网络
       (如手机热点、家庭网络、VPN)
    2) 重新执行:
         git push -u origin main
    3) 若提示认证，输入 GitHub 用户名 + PAT (不要用密码)
  说明: GitHub 已不支持密码认证，必须用 PAT。

方案 4: 使用 GitHub Desktop / VS Code 推送
  说明: 图形客户端内置认证与代理处理，
        可能在当前网络下更易成功。
