五、视频内容结构（参照 gen_video.py 源码）
--------------------------------------------------
【第一段：读流程 t=0~12s】make_frame → draw_* 系列函数
  画面布局：
    顶部：步骤标题（STEPS 数组，8 步）
    中部上：4 条线程跑道（Main / SendLoop / OnData / FrameGapLoop）
      - run 模式：彩色圆点从左往右移动
      - wait 模式：跑道变红底 + "阻塞中…" 闪烁
      - idle 模式：灰色静止
    中部中：共享内存区 6 个格子
      sp[lock(io)] / buf[lock(gate)] / curSlave[volatile] /
      running[volatile] / lastDataTicks[Interlocked] / frameReceived[AutoResetEvent]
      每个格子带锁图标，锁的颜色 = 当前持锁线程颜色
    中部下：帧间静默进度条（3.5 字符=3.65ms）+ 解析输出
    底部：电影式字幕（SUBS 数组，14 句解说词，随时间切换）

  关键时间点（参照 SUBS / STEPS）：
    t=0.0  SendLoop 写 curSlave=0x01
    t=0.4  持 io 锁发请求帧
    t=1.4  SendLoop 阻塞等 frameReceived（跑道变红）
    t=1.6  OnData 持 io 锁读应答（分 3 批）
    t=3.1  OnData 持 gate 锁入 buf + Interlocked 写 lastDataTicks
    t=4.8  FrameGapLoop 判静默≥3.65ms → 持 gate 锁处理残帧
    t=5.5  迟到字节想进 buf，gate 锁被占，OnData 等待（演示锁竞争）
    t=6.2  Drain 切走 9 字节完整帧
    t=7.6  Handle 校验 CRC + 比对 curSlave → 解析温湿度 25.3℃/60.5%RH
    t=8.3  frameReceived.Set() 灯变绿
    t=9.0  SendLoop 唤醒，idx→0x02 发下一帧
    t=10.6 一轮完成，循环

【第二段：写流程 t=12~24s】draw_write_frame
  画面布局类似，但线程跑道换成：
    按钮A/B (CmdLoop) / WriteLoop / ExecuteWrite / 后台打印线程
  共享内存区换成：
    writeQueue[ConcurrentQueue] / activeWrite[volatile] / sp[lock(io)] /
    wr1.Completed / wr2.Completed / wr.Ack

  关键时间点（参照 SUBS_W / STEPS_W）：
    t=0    按钮A new wr1 → Enqueue → 立即返回"已提交"
    t=1.5  按钮B new wr2 → Enqueue → 立即返回（不阻塞）
    t=3.0  后台线程A/B 各自 wr.Completed.Wait（闭包捕获自己的 wr）
    t=4.5  WriteLoop TryDequeue wr1 → ExecuteWrite(wr1) → activeWrite=wr1
    t=5.5  sp.Write(wr1.Frame) → wr1.Ack.WaitOne 等回显
    t=7.0  Handle 比对 activeWrite.Frame 整帧一致 → AckOk=true → Ack.Set()
    t=8.0  wr1.Result=true → wr1.Completed.Set() → 唤醒后台线程A
    t=9.5  WriteLoop 取 wr2 串行执行（不会与 wr1 冲突）
    t=11.0 wr2.Completed.Set() → 唤醒后台线程B
    t=12.5 完成

  核心演示点：多按钮并发提交、WriteLoop 串行执行、每个 wr 独立 Completed
  信号互不干扰、activeWrite 防止回显错配。
