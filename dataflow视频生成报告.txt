一、源文件分析
================================================================================

1.1 dataflow.html 结构
--------------------------------------------------------------------------------
  包含 2 个 SVG 动画场景：
    场景1：Modbus RTU 多从站轮询 · 数据流转动态演示（循环 12s）
    场景2：多按钮写操作 · 队列+独立信号异步通信（循环 14s）

  动画技术：
    - SVG 元素（rect/text/circle）+ JS requestAnimationFrame
    - 时间线驱动：steps 数组定义关键时间点的文字
    - move() 函数在时间区间 [t0,t1] 内线性插值移动圆点
    - setActive() 切换模块框的高亮状态
    - fillBuf()/fillQ() 切换缓冲区格子的填充状态

1.2 场景1 时序（12s 循环）
--------------------------------------------------------------------------------
  t=0     ① SendLoop 发 0x01 请求帧（Tx→Sp）
  t=1.5s  ② 从站应答字节流入（Sp→Rx，分3批）
  t=3.0s  ③ OnData 追加 buf（Rx→buf，buf 填充 3/6/9）
  t=4.8s  ④ FrameGapLoop 检测静默（静默计时条 0→200px）
  t=6.2s  ⑤ Drain 切帧（buf→Drain）
  t=7.6s  ⑥ Handle 解析温湿度
  t=9.0s  ⑦ Set 信号唤醒发送线程（Drain→Tx）
  t=10.6s 循环

1.3 场景2 时序（14s 循环）
--------------------------------------------------------------------------------
  t=0     ① 按钮A 提交 wr1（btnA→queue）
  t=1.5s  ② 按钮B 提交 wr2（btnB→queue）
  t=3.0s  ③ 后台线程等 Completed
  t=4.5s  ④ WriteLoop 取 wr1（queue→wl）
  t=5.5s  ⑤ ExecuteWrite 发写命令（wl→ex→sp2）
  t=7.0s  ⑥ Handle 收回显（sp2→hd）
  t=8.0s  ⑦ 唤醒后台线程A（hd→ex→bg）
  t=9.5s  ⑧ WriteLoop 取 wr2
  t=11.0s ⑨ wr2 完成唤醒后台线程B
  t=12.5s 循环


二、生成方案
================================================================================

2.1 方案选择
--------------------------------------------------------------------------------
  方案A：Chrome headless --screenshot 截图
    问题：SVG 动画靠 requestAnimationFrame 驱动，headless 截图是静态的，
          无法捕获动画随时间的变化。
    否决。

  方案B：Puppeteer/Playwright 录屏
    问题：未安装，需要 npm 安装，环境依赖重。
    否决。

  方案C：Python + cv2 复刻动画逻辑逐帧绘制
    优点：imageio/PIL/cv2 已安装；完全控制每一帧；可精确复刻时序。
    采用。

2.2 实现细节
--------------------------------------------------------------------------------
  - 分辨率：1000×640（与 SVG viewBox 1000×620 接近，加 20px 边距）
  - 帧率：30 fps
  - 总时长：12s（场景1）+ 2s（间隔）+ 14s（场景2）= 28s
  - 总帧数：840
  - 编码：mp4v（MPEG-4 Part 2，兼容性好）

2.3 关键技术点
--------------------------------------------------------------------------------
  - 中文字体：用 PIL.ImageFont 加载 C:\Windows\Fonts\msyh.ttc（微软雅黑）
  - 文字绘制：cv2 不支持中文，用 PIL 画文字再转回 cv2（BGR↔RGB 转换）
  - 模块框：draw_box() 画填充矩形 + 边框，active 时边框变金色加粗
  - 移动圆点：move_dot() 在 [t0,t1] 内线性插值，区间外隐藏
  - 缓冲区格子：fillBuf()/fillQ() 按 i<n 切换填充色
  - 静默计时条：按时间进度填充宽度 0→200px


三、回头审视（主动检查副作用）
================================================================================

3.1 颜色转换 BGR vs RGB
--------------------------------------------------------------------------------
  cv2 用 BGR，PIL 用 RGB，html 用 CSS 颜色（RGB 顺序）。
  脚本中 C_BG = (32, 20, 15) 是 BGR，对应 #0f1420 = RGB(15,20,32)。
  draw_text 中 color[2],color[1],color[0] 把 BGR 转 RGB 给 PIL。
  ✓ 颜色正确。

3.2 时间映射
--------------------------------------------------------------------------------
  场景1：t ∈ [0, 12s) → now_ms = (t % 12) * 1000
  间隔：t ∈ [12, 14s) → 黑帧 + 提示文字
  场景2：t2 = t - 14, now_ms = (t2 % 14) * 1000
  ✓ 边界 t=12s 走间隔分支，t=14s 走场景2分支，无重叠。

3.3 move_dot 边界
--------------------------------------------------------------------------------
  now < t0 或 now > t1：隐藏，不画。
  now == t0：k=0，画在 from。
  now == t1：k=1，画在 to。
  ✓ 闭区间，无越界。

3.4 fillBuf 边界
--------------------------------------------------------------------------------
  now < 3100: 0
  3100 ≤ now < 3500: 3
  3500 ≤ now < 3900: 6
  3900 ≤ now < 6200: 9
  else: 0
  cell 有 8 个，fill_n=9 时 i<9 对 8 个 cell 全亮（i=0..7）。
  ✓ fill_n=9 不会越界（i<9 对 8 个 cell 全亮）。

3.5 fillQ 边界
--------------------------------------------------------------------------------
  4 个 cell，fill_q 最大 2，i<2 亮 2 个。
  ✓ 无越界。

3.6 字体路径
--------------------------------------------------------------------------------
  C:\Windows\Fonts\msyh.ttc 存在（验证过），fallback simhei.ttf。
  ✓ 中文字体可用。

3.7 VideoWriter 释放
--------------------------------------------------------------------------------
  writer.release() 在循环后调用。
  ✓ 资源释放。

3.8 帧率与时长一致性
--------------------------------------------------------------------------------
  FPS=30, TOTAL=28s → 840 帧。
  验证输出：帧数 840，fps 30.0，宽 1000，高 640。
  ✓ 一致。

五、与原 html 的差异
================================================================================

5.1 动画连续性
--------------------------------------------------------------------------------
  html：requestAnimationFrame ~60fps，平滑。
  mp4：30fps，略逊但流畅度可接受。
  差异：圆点移动略有阶梯感（30fps vs 60fps）。

5.2 循环行为
--------------------------------------------------------------------------------
  html：无限循环（% LOOP）。
  mp4：场景1 播 1 遍 + 间隔 + 场景2 播 1 遍，不循环。
  原因：视频文件本身不循环，播放器可设置循环。
  差异：mp4 是单次播放，html 是无限循环。

5.3 两个场景的呈现
--------------------------------------------------------------------------------
  html：两个 SVG 同屏上下排列（实际是顺序排列，浏览器滚动）。
  mp4：两个场景顺序播放，中间 2s 间隔黑帧。
  差异：mp4 是时间顺序，html 是空间顺序。

5.4 文字渲染
--------------------------------------------------------------------------------
  html：浏览器渲染，抗锯齿清晰。
  mp4：PIL 渲染，抗锯齿略逊。
  差异：mp4 文字边缘略有锯齿，可读性可接受。
