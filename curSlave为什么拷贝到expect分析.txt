curSlave 为什么拷贝到局部变量 expect 而不直接读字段
================================================================================

分析对象：F:\chenbo\Program.cs Handle 中 expect = curSlave 的设计

一、用户问题
================================================================================
先前那为啥 curSlave 不直接拿（直接读字段）？


二、结论：curSlave 拷贝到 expect 是因为后续要多次使用，且要"快照一致性"
================================================================================
curSlave 和 pollActive 都是值类型，但使用方式不同：
  - pollActive：只读一次，用在 if 判断里，直接读字段最简单
  - curSlave：读一次赋给 expect，后续 expect 被多次使用（校验 + 日志），需要快照一致

拷贝到 expect 的原因：
  1. 后续多次使用 expect（校验 + 日志输出），每次直接读 curSlave 可能拿到不同值
  2. 校验和日志要用同一个值，保证一致性
  3. expect 是 byte（值类型），拷贝无空引用风险，和 activeWrite 的拷贝原因不同


三、curSlave vs pollActive 的使用方式对比
================================================================================

3.1 pollActive：只读一次
--------------------------------------------------------------------------------
  else if (pollActive) pollAck.Set();
  // pollActive 只在这一行用，读一次就完了。
  // 直接读字段 = 拿最新值 = 最安全。
  // 不需要局部变量（只读一次，没有"多次使用要一致"的问题）。

3.2 curSlave：读一次，后续多次使用
--------------------------------------------------------------------------------
  byte expect;
  ...
  else
      expect = curSlave;           // ① 读 curSlave 赋给 expect
  if (frame[0] != expect)          // ② 用 expect 校验
  {
      Console.WriteLine($"...当前在等从站 {expect:X2}...");  // ③ 用 expect 日志
      return;
  }
  // expect 可能还在后续代码中被用（虽然当前没用到）

  curSlave 被读一次赋给 expect，expect 后续被用了 2 次（校验 ② + 日志 ③）。
  如果每次直接读 curSlave：
    if (frame[0] != curSlave)                    // ② 读 curSlave（可能值 A）
        Console.WriteLine($"...{curSlave:X2}");  // ③ 读 curSlave（可能值 B！）
  ② 和 ③ 可能拿到不同的值！校验说"不匹配"但日志打印的是另一个值，语义不一致。


四、为什么"多次使用"需要快照
================================================================================

4.1 场景：不拷贝，多次直接读 curSlave
--------------------------------------------------------------------------------
  t=50.0  Handle: if (frame[0] != curSlave)   // curSlave=1, frame[0]=1 → 相等，不进 if
  t=50.1  SendLoop: curSlave = 2（下一轮轮询从站2）
  t=50.2  Handle: Console.WriteLine($"{curSlave}")  // curSlave=2！打印"从站2"
  // 但校验时 curSlave 是 1，日志时是 2，语义错乱

  或者：
  t=50.0  Handle: if (frame[0] != curSlave)   // curSlave=1, frame[0]=2 → 不等，进 if
  t=50.1  SendLoop: curSlave = 2
  t=50.2  Handle: Console.WriteLine($"当前在等从站{curSlave}")  // curSlave=2！
  // 日志说"当前在等从站2"，但校验时在等从站1，日志误导

4.2 场景：拷贝到 expect，保证一致
--------------------------------------------------------------------------------
  t=50.0  Handle: expect = curSlave   // expect=1（快照）
  t=50.1  SendLoop: curSlave = 2
  t=50.2  Handle: if (frame[0] != expect)  // expect=1, frame[0]=2 → 不等
  t=50.3  Handle: Console.WriteLine($"当前在等从站{expect}")  // expect=1
  // 校验和日志都用 expect=1，语义一致："当前在等从站1，收到从站2的应答，忽略"

4.3 核心区别：一次读 vs 多次读
--------------------------------------------------------------------------------
  pollActive：只读一次（if 判断），不需要快照
  curSlave：读一次后多次用（校验+日志），需要快照保证一致


五、那 pollActive 也拷贝会怎样
================================================================================

5.1 pollActive 拷贝
--------------------------------------------------------------------------------
  bool active = pollActive;
  if (active) pollAck.Set();
  // 只用了一次（if 判断），拷贝没有带来好处
  // 反而有"旧值"风险（前一轮分析过）：拷贝后 pollActive 变了，active 是旧值

5.2 pollActive 直接读
--------------------------------------------------------------------------------
  if (pollActive) pollAck.Set();
  // 只读一次，拿最新值，无旧值风险
  // 不需要快照（只用一次）

5.3 结论
--------------------------------------------------------------------------------
  pollActive 只用一次 → 直接读最安全（拿最新值）
  curSlave 用多次 → 拷贝最安全（保证一致）


六、那 curSlave 直接读（不拷贝）会出错吗
================================================================================

6.1 功能上不会出错
--------------------------------------------------------------------------------
  if (frame[0] != curSlave)   // 直接读，拿最新值
  // 即使 curSlave 此刻变了，校验结果只是"通过/不通过"
  // 通过 → 继续处理（Set pollAck）
  // 不通过 → return（忽略）
  // 两种结果都不会崩溃，不会误 Set（pollActive 已经守住了 Set 的入口）

6.2 但日志会语义错乱
--------------------------------------------------------------------------------
  校验时 curSlave=1（通过），日志时 curSlave=2（打印"在等从站2"）
  用户看日志会困惑："明明在等从站2，为什么收到了从站1的应答还处理了？"
  实际是"在等从站1时收到从站1应答，处理过程中 curSlave 变了"

6.3 所以拷贝是为了"日志一致性"不是"功能正确性"
--------------------------------------------------------------------------------
  功能正确性由 pollActive 守住（Set 的入口）
  curSlave 拷贝到 expect 是为了校验+日志用同一个值，避免日志误导
  是"防御性编程"的好习惯，不是"必须"的


七、总结：三种变量的读取策略
================================================================================

  ┌──────────────┬──────────┬──────────┬──────────────────────────────┐
  │ 变量         │ 类型     │ 使用次数 │ 策略                         │
  ├──────────────┼──────────┼──────────┼──────────────────────────────┤
  │ activeWrite  │ 引用class│ 多次     │ 拷贝局部变量（防 null 崩溃） │
  │ curSlave     │ 值 byte  │ 多次     │ 拷贝局部变量（防日志语义错乱）│
  │ pollActive   │ 值 bool  │ 一次     │ 直接读字段（拿最新值最安全） │
  └──────────────┴──────────┴──────────┴──────────────────────────────┘

  ★ activeWrite 拷贝：防崩溃（NullReferenceException）
  ★ curSlave 拷贝：防语义错乱（校验和日志用同一个值）
  ★ pollActive 直接读：防旧值误判（只读一次，拿最新最安全）

  三种策略都是正确的，针对各自的使用场景和风险。
