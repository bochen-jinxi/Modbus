============================================================
ExecuteWrite 局部变量创建时机 详解
============================================================
日期：2026-11-02
相关代码：F:\chenbo\Program.cs 的 ExecuteWrite 方法

------------------------------------------------------------
一、问题
------------------------------------------------------------

ExecuteWrite 里的局部变量：
    byte slave = wr.Slave;
    ushort addr = wr.Addr;
    bool on = wr.On;
    byte[] frame = wr.Frame;

是因为 WriteLoop 被线程调用、且 ExecuteWrite 被线程调用，
才创建这些局部变量的吗？

------------------------------------------------------------
二、结论
------------------------------------------------------------

不是"因为被线程调用才创建"。
是"方法被调用就创建栈帧，栈帧里就分配局部变量"。
跟是不是线程调用无关。

任何方法被调用（不管在哪个线程、不管是不是线程入口），
CLR 都会在当前线程的栈上分配栈帧，栈帧里分配所有局部变量。
方法返回时栈帧弹出，局部变量销毁。

------------------------------------------------------------
三、方法调用 = 创建栈帧 = 分配局部变量
------------------------------------------------------------

CLR 执行方法调用的步骤：
1. 在当前线程的栈上分配一个"栈帧"（stack frame）
2. 栈帧里分配这个方法的所有局部变量的空间
3. 方法返回时，整个栈帧被弹出，局部变量销毁

WriteLoop 线程的栈结构：

    ┌─ WriteLoop 栈帧 ──────────────┐
    │  wr (TryDequeue 取出的)       │
    │  ...                          │
    │  ┌─ ExecuteWrite 栈帧 ────────┐  ← 调用 ExecuteWrite 时压入
    │  │  wr (参数)                 │
    │  │  slave                     │  ← 这些在这里分配
    │  │  addr                      │
    │  │  on                        │
    │  │  frame                     │
    │  │  attempt                   │
    │  └────────────────────────────┘  ← ExecuteWrite 返回时弹出
    └────────────────────────────────┘

------------------------------------------------------------
四、跟"是不是线程调用"无关
------------------------------------------------------------

情况1：主线程直接调
    void Foo() {
        ExecuteWrite(someWr);
        // 主线程栈上创建 ExecuteWrite 栈帧，局部变量在主线程栈
    }

情况2：WriteLoop 线程调
    void WriteLoop() {
        while (running) {
            TryDequeue(out var wr);
            ExecuteWrite(wr);
            // WriteLoop 线程栈上创建 ExecuteWrite 栈帧，局部变量在 WriteLoop 线程栈
        }
    }

两种情况局部变量都会创建，只是"在哪个线程的栈上"不同。
不是"因为是线程调用才创建"。

------------------------------------------------------------
五、跟"线程"真正相关的是栈的位置
------------------------------------------------------------

- 主线程调用 → 栈帧在主线程的栈上
- WriteLoop 线程调用 → 栈帧在 WriteLoop 线程的栈上
- 每个线程有独立的栈，互不干扰

所以 ExecuteWrite 里的 slave/addr/on/frame 是 WriteLoop 线程栈上的，
别的线程看不到、改不了。

这是线程安全的一个基础：局部变量天然线程隔离，不用加锁。

------------------------------------------------------------
六、为什么要把 wr 的字段拷贝到局部变量
------------------------------------------------------------

    byte slave = wr.Slave;
    ushort addr = wr.Addr;
    bool on = wr.On;
    byte[] frame = wr.Frame;

其实不是必须的，直接用 wr.Slave、wr.Addr 也能跑。
这样写的好处：

1. 可读性：后面代码用 slave 比 wr.Slave 简洁。

2. 避免多次访问对象字段：虽然 JIT 可能优化，但显式拷贝到局部变量后，
   访问的是栈上变量（更快），不用每次去堆上读字段。

3. 稳定快照：wr 是引用，理论上别的线程能改 wr.Slave（虽然这里不会），
   拷贝到局部变量就固定了这次执行用的值。

------------------------------------------------------------
七、栈帧生命周期
------------------------------------------------------------

WriteLoop 是死循环，但 ExecuteWrite 不是。

    static void WriteLoop()
    {
        while (running)
        {
            TryDequeue(out var wr);
            ExecuteWrite(wr);   ← 第1次：创建栈帧A，执行完弹出
            ...
            TryDequeue(out var wr2);
            ExecuteWrite(wr2);  ← 第2次：创建栈帧B（可能复用同一块栈空间），执行完弹出
        }
    }

每次调用 ExecuteWrite：
- 压入新栈帧（或复用弹出的空间）
- 分配局部变量
- 执行
- 弹出栈帧，局部变量"销毁"（空间可被下次调用复用）

所以多个 wr 串行执行时，ExecuteWrite 的局部变量不会累积，
每次调用是独立的栈帧。

------------------------------------------------------------
八、对比：什么"才"跟线程相关
------------------------------------------------------------

| 东西                | 跟方法调用相关 | 跟线程相关 |
|---------------------|--------------|-----------|
| 局部变量是否存在    | ✓ 方法调用就创建 | ✗ 无关    |
| 局部变量在哪个栈上  | ✗             | ✓ 当前线程的栈 |
| 局部变量线程隔离    | ✗             | ✓ 每线程独立栈 |
| static 字段         | ✗             | ✓ 多线程共享，需同步 |
| 堆上对象            | ✗             | ✓ 多线程共享，需同步 |

局部变量：方法调用就创建，在调用它的那个线程的栈上，天然线程隔离。
static 字段/堆对象：跟线程无关，多线程共享，需要锁/信号量同步。

------------------------------------------------------------
九、一句话总结
------------------------------------------------------------

ExecuteWrite 的局部变量 slave/addr/on/frame 是"方法调用创建栈帧"时分配的，
不是"因为线程调用才创建"。跟是不是线程调用无关。
真正跟线程相关的是"栈帧在哪个线程的栈上"——
WriteLoop 调 ExecuteWrite，栈帧在 WriteLoop 线程栈上，
局部变量天然线程隔离，别的线程看不到。
